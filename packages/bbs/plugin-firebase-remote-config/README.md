# Firebase Remote Config

Android-first NativePHP Mobile plugin for `com.santhosh.nativeblog`. It reuses
the existing default FirebaseApp and BoM `33.12.0`, with firebase-config added
without a separate module version or Analytics. Existing Google authentication
asset copying supplies google-services.json.

## PHP API

```php
use Bbs\FirebaseRemoteConfig\Facades\FirebaseRemoteConfig;

$availability = FirebaseRemoteConfig::isAvailable();
$info = FirebaseRemoteConfig::getInfo();
$defaults = FirebaseRemoteConfig::setDefaults([
    'welcome_message' => ['type' => 'string', 'value' => 'Welcome'],
    'show_media_optimizer' => ['type' => 'boolean', 'value' => true],
    'media_image_quality' => ['type' => 'integer', 'value' => 80],
]);
$status = FirebaseRemoteConfig::getStatus($defaults->id);
// After cached initialization and successful default registration:
$quality = FirebaseRemoteConfig::getInteger('media_image_quality');
$message = FirebaseRemoteConfig::getString('welcome_message');
$flag = FirebaseRemoteConfig::getBoolean('show_media_optimizer');
$decimal = FirebaseRemoteConfig::getDecimal('some_decimal');
```

This illustrates independent calls, not a sequence that waits for asynchronous
completion. Poll each mutation until terminal before starting another.
Configure, SetDefaults, Fetch, Activate and FetchAndActivate are observable
asynchronous operations. Optional IDs are lowercase RFC-variant UUIDs; omitted
IDs are generated by PHP. Keep an ID when its acknowledgement is uncertain.

`configure()` defaults to a 12-hour interval and 60-second SDK timeout. Interval
0 is an explicit development setting. Fetch never activates. Activate false
is successful unchanged. FetchAndActivate performs explicit fetch then
activation, checking the total deadline before its second stage.

Typed getters return success, key, type, value, source and errorCode.
getValues maps selected keys to requested types. The exact SDK value wrapper
supplies both the conversion and source: remote, default or static. Bad
conversion fails instead of silently labeling a replacement value remote.
Application code supplies its own validated fallback and labels it separately.
JSON is a string requiring application decoding/validation, not a native type.

The nine bridge names and exact wire shapes are in [CONTRACT.md](CONTRACT.md).
Unexpected fields, inconsistent flags, mismatched correlation and malformed
native responses fail closed. Exceptions, payloads, private paths and
credentials are not exposed in bridge results.

## Bounds and execution

- Request 8192 bytes, response 16384 bytes, JSON depth 16.
- Selected keys/defaults: 1–32; keys: 1–128 ASCII bytes, starting with a letter
  or underscore, followed by letters, digits or underscores.
- Strings: at most 1024 UTF-8 bytes. Booleans are actual booleans. Integers are
  actual integers within ±9007199254740991; integral floats and strings fail
  an integer request. Decimals are finite doubles.
- Interval: integer 0–604800 seconds; SDK fetch timeout: integer 1–120 seconds.
- Cached initialization, Configure, SetDefaults and Activate total deadlines:
  15 seconds. Fetch: actual SDK timeout +5; combined: timeout +20.

Runtime owns one application-context SDK/store pair, a bounded single-worker
queue and an independent deadline executor. UI-thread calls fail before SDK
or disk work. NativePHP's existing BridgeResponse.success data-map convention
is used. No automatic fetch, activation, real-time listener, or Analytics is
introduced. Initialization reads the SDK cache; successful local default
registration is required for typed reads and remote operations in each process.

PHP bounds the actual encoded wire string. NativePHP has already decoded the
JSON before Kotlin sees it, so Kotlin bounds reconstructed compact JSON and
validates Unicode separately. Those byte measurements can differ for escaped
JSON. Kotlin preserves strict integer/decimal token distinction.

## Durable history and uncertainty

Admission persists before acknowledgement. One nonterminal mutation is allowed;
same retained ID and identical typed payload replay without another SDK start.
Changed payload conflicts and a different concurrent request is BUSY. Canonical
fingerprints preserve typed identity. History stores fingerprints and results,
not parameter/default values; it is not encryption or a secret store.

The private no-backup AtomicFile history is bounded to 50 records/65536 bytes.
Oldest terminal records are pruned; callers must not reuse old or evicted IDs.
There is one process owner and caller locking, not a cross-process file lock.
Commits are synced and read back. Corrupt history is preserved and fails
closed; a failed write freezes the store until process restart reloads actual
state. Stale callbacks cannot overwrite newer progress or terminal records.

After restart, pending/running records become PROCESS_INTERRUPTED before
polling. No SDK mutation is replayed automatically and no activation outcome
is invented. Fresh default registration is required in the new process;
replaying an old successful defaults request does not restore readiness.

Timeout produces a durable terminal record, but noncancellable SDK work can
still settle later. The SDK busy gate stays closed to new mutations until it
does. Late fetch cannot start activation after a combined deadline. Late
activation/configuration can change actual SDK state without changing the
timed-out record; explicit reads after settlement observe actual values.
Reads are blocked while default registration or activation can change them.
Queue/callback time counts toward deadlines, but a stalled filesystem write or
lock holder cannot be interrupted by the timer mechanism.

Narrow correlated runtime/persistence control failures retain the ID and become
PHP-only nonterminal `unconfirmed`, as do absent/malformed acknowledgements.
In that state accepted=false means acceptance is uncertain, not proof of no
execution. Poll the same ID with a bound, then require explicit recovery.
Never fabricate rejection, not_found, completion or a second automatic request.

## App demo and validation

The application registers this package with root Composer and explicitly in
NativeServiceProvider. All nine functions appear in NativePHP discovery and
generated Kotlin registration; the normal Android debug build compiled them.
The app demo and manual acceptance checklist are in
[docs/firebase-remote-config.md](../../../docs/firebase-remote-config.md).
Home uses the welcome/flag; media jobs sample validated quality only for new
JPEG/WebP requests. Authorization stays independent of feature flags.

Verified pre-demo laptop results: 429 package tests/1091 assertions; 351 Android
tests with no failures/errors/skips; 228 application regression tests/1578
assertions after registration. These use controlled cases and do not prove a
real Firebase-console fetch/activation, cache restart or notification delivery.
Those manual scenarios remain pending until executed and recorded.

```powershell
php .\vendor\phpunit\phpunit\phpunit --configuration .\packages\bbs\plugin-firebase-remote-config\phpunit.xml
```

Use the test Gradle init script with remoteConfigTestSourceDir. After normal
registration, omit remoteConfigMainSourceDir: production sources are generated
by the plugin compiler, and adding them again duplicates declarations. Shared
vectors cover PHP/Kotlin contracts; native tests cover conversion, Google Tasks,
storage, replay, deadlines, late callbacks, runtime ownership and bridge targets.

NativePHP 4.2.0's plugin validator unconditionally requires ios.min_version for
Android-only manifests. The observed validation error was limited to that
unused field; vendor code was inspected. The Android-only platforms list is
preserved. Manifest tests, discovery and generated Android compilation provide
the applicable checks without adding false iOS support or patching vendor.
